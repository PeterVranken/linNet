\chapter{Installation}

A valid \linnet{} installation looks like this: The \linnet{} application
is a simple executable file plus a folder with resources for the Octave
code generator; this folder is called \file{private} and is located next
to the \linnet{} executable file, i.e., both are siblings in the same
parent directory. The environment variable \ident{LINNET\_BIN} points to
this parent directory.

Accordingly, this is what you have to do to install \linnet{}:

Create an empty folder, the installation directory, e.g.,
\file{c:\bs{}ProgramFiles\bs{}linNet} (Windows) or \file{/usr/\-bin/\-linNet}
(Linux, Mac OS). Copy the \linnet{} executable file and the folder
\file{private} into this directory. Create a persistent environment
variable \ident{LINNET\_BIN} and assign the path to the installation
directory.

Linux and Mac OS users need to open a shell and run command \code{chmod +x
/usr/bin/linNet/linNet} to make the binary file executable.

The usual way to use \linnet{} is to run it from a shell window. You will
probably organize your input circuits in a folder or a set of such and
\code{cd} to this folder. To run \linnet{} in this scenario, it is useful to place a reference to the installation
directory in the system environment variable \ident{PATH}. In our example
you'd append \code{;\bs{}ProgramFiles\bs{}linNet} (Windows) or
\code{:/usr/bin/linNet} (Linux, Mac OS) to the current value of this
variable.

The definition of a shell command-alias pointing to the \linnet{}
executable file can be a reasonable alternative to extending the
environment variable \ident{PATH}.

If environment variable \ident{LINNET\_BIN} is not set then \linnet{}
makes an attempt to find its resources via the path to itself. However, it
depends on the system, the shell in use and the way the command is typed,
whether this information is completely passed to the application or not.
If it can't find out where to find itself it'll refuse to generate Octave
code as it lacks the folder \file{private} with code
templates.\footnote{There are system specific functions which let an
application find out, where its executable file is located, e.g.,
\ident{GetModuleFileName} for Windows, but the use of such functions would
make the source code of \linnet{} platform dependent. This price is too
high for a slightly simpler installation.} Not setting the environment
variable can be a safe option if you decide to run \linnet{} solely from a
shell window with an alias, which expands to the full, absolute path of
the executable.

\section{Windows}

\subsection{Pre-built executables}

An installation archive for \linnet{} can be downloaded from the GibHub
Releases page,
\href{https://github.com/PeterVranken/linNet/releases}{https://\-github.com/\-Peter\-Vranken/\-linNet/\-re\-leases}.
The archive contains pre-build, ready-to-use executable files for Windows
(DEBUG and PRODUCTION compilation). The executable files are already
bundled with the resources folder \file{private} so that the installation
reduces to extracting the contents of the archive to a location of choice,
preferably \file{c:\bs{}\-Program\-Files}, and setting the environment
variable \ident{LINNET\_BIN}; it would be set to
\file{c:\bs{}\-Program\-Files\bs{}\-linNet\bs{}\-bin\bs{}\-win\bs{}\-PRODUCTION}
if the suggested installation folder is used. The chosen installation path
should not contain blanks.

\subsubsection{How to set the environment variables}

Open a PowerShell window and execute the following commands, replacing the
example installation directory with the actual location of your \linnet{}
installation: 

\begin{lstlisting} [%language=bash,
basicstyle=\ttfamily\footnotesize]
# Assign the chosen installation directory.
$linnet = "C:\ProgramFiles\linNet\bin\win\PRODUCTION"
# Set LINNET_BIN permanently for the current user.
[System.Environment]::SetEnvironmentVariable("LINNET_BIN", $linnet, "User")
# Append the linNet binary directory to PATH.
$path = [System.Environment]::GetEnvironmentVariable("Path", "User")
[System.Environment]::SetEnvironmentVariable("Path", $path+";$linnet", "User")
\end{lstlisting}

After executing these commands, open a new PowerShell window for the
changes to take effect. You can verify the configuration using:

\begin{lstlisting} [%language=bash,
basicstyle=\ttfamily\footnotesize]
echo $env:LINNET_BIN
echo $env:PATH
linNet --help --version
linNet -o -l $env:LINNET_BIN\..\..\..\circuits\2poleLP\2poleLP.cnl
dir 2poleLP*
\end{lstlisting}

\subsection{Required DLLs}

The build of \linnet{} has the executable file \file{linNet.exe} as only
product. This executable file is however not self-contained; the
application is linked against the compiler's C libraries, which in case of
the GNU compiler collection build on some Windows DLLs. These DLLs need to
be available in order to execute \linnet{}. Normally, this should always
be the case. In the rare situation that such a library should be missing on
your system then a way out will be installing the GCC port of MinGW
and to rebuild \linnet{}. This would bring all required DLLs into your
computer. If you can run the simplest \ident{helloWorld} application
compiled with GCC then you should also be able to run \linnet{}.

The 64 Bit build of \linnet{} with GCC mingw-w64-gcc-13.2.0-x64 on a
Windows 11 system loads these DLLs:\newline

\noindent
\file{C:\bs{}WINDOWS\bs{}SYSTEM32\bs{}ntdll.dll}\newline
\file{C:\bs{}WINDOWS\bs{}System32\bs{}KERNEL32.DLL}\newline
\file{C:\bs{}WINDOWS\bs{}System32\bs{}KERNELBASE.dll}\newline
\file{C:\bs{}WINDOWS\bs{}System32\bs{}ucrtbase.dll}\newline

Other target platforms or other compiler releases will probably require
other DLLs. For example, the build with GCC
mingw-w64-gcc-mcf\_20260501\_16.1.0\_x86-msvcrt or
mingw-w64-\-gcc-\-mcf\_\-20260501\_\-16.1.0\_x64-msvcrt, also on Windows
11, requires an additional DLL, which is located in the compiler's
installation directory:\newline

\noindent
\file{libmcfgthread-2.dll}\newline

To run the \linnet{} executable in this scenario, you would either have to
copy that particular DLL into the folder, where \file{linNet.exe} is
located or you would need to add folder \file{mingw32\bs{}bin} or
\file{mingw64\bs{}bin} in the installation of GCC to the system
environment variable \ident{PATH}, so that Windows can find this DLL.

\subsection{Start from Windows Explorer (file name association)}

If you want to start the computation of transfer functions directly from
the Windows Explorer then you can add a file class definition to the
Windows registry. It'll extend the context menu entries of the Windows
File Explorer for circuit netlist files. By double-click you can load the
netlist file into a text editor. A right-click on the file opens the
context menu and you can run the computation with a click on \code{Run
linNet}. Please note, if starting \linnet{} this way Windows will swallow
all the program output and you will have to open the log file after the
computation to find out if the computation was successful.

The template for a Windows registry script, that creates an appropriate
file class definition, is available in GitHub as

(visited Sep 22, 2026) and it can be found as \file{doc/\-linNet.reg} in the
