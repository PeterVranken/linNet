The netlist file contains two unconnected circuits. They are nearly
identical; it are input followers using an op-amp with direct feedback
from output to inverting input. The only difference is an additional
voltage source in the feedback of the second op-amp, which results in an
offset between in- and output voltage. Both circuits have a resistor in
parallel to the input voltage. Due to the infinite input impedance of the
(ideal) op-amp, this resistor becomes the input impedance of the circuit.

The netlist exists in two variants. The other file
link:unconnectedCircuits.noGnd.cnl[] has the same circuit but node
`K01_gnd` is named `K01`. This leads to an interesting and important
link:unconnectedCircuits.noGnd.log[error message]; the circuit can't be
calculated.

Further observations with this netlist:

. Including two unconnected circuits in a single netlist does not affect
the calculated results compared to placing each circuit in its own netlist
file. However, it does affect how the
link:unconnectedCircuits/Ambiguous.m[results] are represented: the result
of one circuit is expressed as a function that also includes known
currents and voltages from the other (unconnected) circuit. Although these
additional terms have a factor of zero, they are still shown in the
output. Conclusion: If there is no functional connection between circuits,
it is preferable to place them in separate netlist files. . The feedback
line of the second op-amp contains a voltage source (which could be the
model of a diode in the true circuit). This leads to a delta in the output
voltage. This is shown correctly in the result, which is: `Uout2(s) =
Uin2(s) + Udelta(s)`. . The shortcut of the inputs produced by
`Rin1=Rin2=0` doesn't affect the result calculation: linNet calculates
with the symbols `Rin1` and `Rin2`, no matter, which value they might
have. Moreover, the demanded result depends neither on `Rin1` nor on
`Rin2` - the resistors impact the input impedances but not the transfer
functions - and so the shortcut would not even hinder Octave from doing
the numeric calculations. . The numeric coupling of the resistor values is
not a functional coupling of the circuits. It remain two unconnected
circuits.

See link:unconnectedCircuits.cnl[netlist file] and
link:unconnectedCircuits.noGnd.cnl[same netlist with injected error] for
more details of the circuit.
